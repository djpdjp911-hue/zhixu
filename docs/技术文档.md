# 01 项目概述

## 问题
学习者手里有课程 PDF、讲义和笔记，遇到问题时却难以快速定位原文；直接问通用聊天机器人，又可能得到没有出处、甚至与课程资料矛盾的答案。更关键的是，“看懂了”不等于“讲得出”和“记得住”。多数 AI 学习工具止步于回答问题，既不检验理解，也不安排复习。

## 作品定位
知序是以学习者自有资料为知识边界的 AI 学习工作台，把一次提问延伸为完整的学习闭环：有据问答 → 理解检验 → 费曼复述 → 间隔复习。每个环节的 AI 输出都能回到原文核对。

## 目标用户
高校学生与自学者：拥有课程讲义、技术文档或研究入门资料，需要在资料范围内获得可信解释，检验自己是否真正理解，并持续复习。示例聚焦 Web 开发课程，使用四份项目原创讲义；平台可导入任意经授权的文本资料。

## 创新点
- 创新点一 · 证据闭环的学习 Agent：Agent 只能通过受限工具读取学习者选择的资料，回答逐句带引用；系统再在本地逐句核验引用支持度，把“AI 说的话有没有出处”变成学习者看得见、点得开的信息。
- 创新点二 · AI 出题 + 原文逐字校验：模型生成的每道题都必须附一句原文引用，系统逐字比对，对不上的题自动淘汰并由规则题补齐，让生成式出题可控、可追溯。
- 创新点三 · 费曼复述、AI 评估与间隔复习联动：学习者用自己的话讲解知识点（支持语音），AI 对照原文按准确性、完整性、理解深度评分并指出遗漏与误解；分数直接驱动 1 → 3 → 7 → 14 → 30 天的复习阶梯。
- 创新点四 · 一套工具定义，两种开放方式：同一组资料工具既供应用内模型 Function Calling 使用，也通过 MCP Server 开放给 Cursor、Claude 等外部 AI 客户端，学习资料成为可被其他 AI 复用的知识源。
- 创新点五 · 模型无关与全程兜底：统一接入 OpenAI 兼容服务（含国产免费模型）与 Gemini，厂商差异自动降级；未配置模型或调用失败时，问答、出题、复述评估都有本地确定性实现，体验不中断。

# 02 需求分析

## 用户故事
- 作为学生，我想就课程资料提问，并看到每句结论来自讲义哪一页，以便放心引用和复习。
- 作为学生，我追问“那它和……有什么区别”时，希望系统理解上文指代。
- 作为学生，我想用题目检验自己是否真的理解，而不只是记住了原句。
- 作为学生，我想用自己的话讲一遍，知道哪里讲漏、哪里讲错。
- 作为学生，我希望系统在合适的时间提醒我复习，而不是学完就忘。
- 作为重视隐私的用户，我希望资料默认留在本机，发送给云端模型前需要我明确同意。

## 功能需求
| 模块 | 需求 |
|---|---|
| 资料 | PDF / Markdown / TXT 导入、粘贴笔记、图片文字识别并人工核对；保留页码与字符位置 |
| 问答 | 限定资料范围；Agent 自主检索；流式作答；引用可点击；逐句核验；连续追问；证据不足拒答 |
| 检验 | AI 出题（薄弱主题优先、原文校验）；规则题兜底；答案依据可回溯 |
| 复述 | 费曼复述（键盘或语音）；AI 或规则评估；遗漏与误解定位到原文 |
| 复习 | 错题次日复习；复述达标后按间隔阶梯巩固；可调整日期与完成状态 |
| 数据 | IndexedDB 本机保存；JSON 备份导出与校验恢复 |

## 非功能需求
- 可信：模型输出可回溯；结构化输出必须通过校验；失败不伪装成成功。
- 可用：未配置模型时完整流程可用；模型失败可一键重试或改用原文检索。
- 安全：密钥只在服务端；资料与学习者输入都视为不可信数据；工具白名单。
- 体验：首字尽快可见；AI 思考过程可视化；键盘可达；桌面与手机适配。
- 约束：单文件 ≤8MB，单份资料 ≤15 万字符，PDF ≤100 页，最多 40 份资料。

# 03 系统架构

## 分层结构
展示层：React 19 + TypeScript。工作台、资料库、证据问答、知识脉络、学习诊断、复习计划六个视图，与原文侧栏、弹窗共用一份 Context 状态。

领域层（lib/）：分块与检索（retrieval）、工具定义与执行（tools）、注入扫描与逐句核验（safety）、学习规则与结构化输出校验（learning）、存储与备份校验（storage）。领域层是纯 TypeScript，可在浏览器、Worker 与 Node 测试中复用。

服务层（app/api/）：study（问答 SSE）、quiz（出题）、feynman（复述评估）、image（图片识别）、status（模型状态）。所有接口校验同源、请求体积与 zod 模式。

模型层（lib/server/）：llm.ts 统一封装 OpenAI 兼容协议与 Gemini；agent.ts 实现 Agent 循环与系统提示。

开放层：scripts/mcp-server.ts 以 stdio 方式实现 MCP 协议，复用领域层工具。

## 问答数据流
1. 浏览器把问题、所选资料与追问上下文（最多 3 轮）发送到 /api/study。
2. 服务端分块并建立本次请求的工具箱，以 SSE 推送 trace（执行步骤）。
3. Agent 第一轮必须调用检索或目录工具；工具结果带稳定 citation 编号返回模型，同时以 evidence 事件推送给前端。
4. 模型回答以 delta 事件逐 token 推送；若模型在调用工具前先输出了文字，服务端发送 reset 清空；推理过程以 thinking 事件推送。
5. 完成后服务端执行引用编号校验与逐句核验，发送 answer 事件，浏览器保存到 IndexedDB。

## 核心数据模型
- StudyDocument / Chunk：资料、页码、章节、原文起止位置。
- StudyAnswer：回答、证据快照、执行记录、模型标签、话题 threadId、逐句核验报告、安全提示。
- QuizQuestion：题目、选项、答案、依据片段、来源（AI / 规则）、考查能力、原文引用。
- ReviewTask：主题、到期日、复习阶段 stage、最近一次复述得分。
- FeynmanFeedback：得分、结论，以及已讲清 / 未讲到 / 需纠正的要点和原文引用。

历史回答保存当时的证据快照，原始资料删除后仍能说明当时引用了什么。

# 04 AI 技术方案：选型与集成

## 模型选型理由
| 选择 | 理由 |
|---|---|
| 默认智谱 GLM（glm-4.7-flash） | 国内直连、免费使用，支持工具调用、流式输出、JSON 输出与深度思考，评审可零成本复现 |
| 视觉模型 glm-4.6v-flash | 免费视觉模型，用于讲义图片文字识别 |
| 实测联调 DeepSeek deepseek-flash | 同一模型覆盖工具调用、JSON 输出、视觉与思考模式，百万上下文、价格低；本作品的真实联调记录基于此模型 |
| 以 OpenAI 兼容协议为主干 | DeepSeek、通义千问、Kimi、硅基流动、本地 Ollama 只需修改 LLM_BASE_URL，避免厂商锁定 |
| 保留 Gemini 适配 | 原生 Function Calling 与 thought signature，便于对比不同模型 |
| 向量检索按需启用 | 仅在配置 embedding 模型时启用；默认 BM25，不为未验证的能力付费 |

选型原则：评审能用免费账号复现；能力不足时自动降级而不是报错；业务逻辑不依赖某一家厂商。

## 统一接入层（lib/server/llm.ts）
对上层只暴露四个能力：createSession（多轮工具对话）、generateJSON（结构化输出）、describeImage（视觉）、embedTexts（向量）。内部处理协议差异：
- 流式：自实现 SSE 解析，兼容 CRLF、半行与中文多字节截断；OpenAI 兼容协议按 index 累积分片到达的 tool_calls 参数。
- 工具选择：首轮发送 tool_choice=required（只允许一个工具时指定函数名）；厂商返回 400 时自动降级为 auto，并在会话内记住。
- 结构化输出：优先 response_format=json_object，不支持时去掉重试；解析时容忍代码块围栏与前后多余文字。
- 推理过程：读取 reasoning_content 实时推送，并随每个助手轮次回传（DeepSeek 思考模式要求带工具的请求回传全部推理，否则返回 400）；思考开关按厂商格式发送；Gemini 原样回放 parts，保留 thought signature。问答展示推理，默认按模型设置思考；出题与复述评估的推理无人查看，默认关闭思考，只有显式设置 LLM_THINKING=enabled 时开启。
- 视觉：智谱使用原始 base64，其他厂商使用 data URL。
- 错误：429、401/403、404、400、超时、网络错误映射为统一错误码与中文提示，前端据此给出可操作的恢复建议。

## Agent 工作流（lib/server/agent.ts）
Agent 最多 5 轮：第 1 轮必须在 search_materials 与 list_materials 中选择；中间轮由模型自主决定继续检索、改写查询、读取原文或作答；最后一轮禁止工具，要求给出结论。每轮最多执行 4 次工具调用。

自主决策的边界由系统保证：模型跳过工具直接作答时，系统代为检索并把结果交回模型重新作答（自动检索兜底）；白名单外的工具调用被拦截并在执行记录中高亮；citation 编号在一次请求内保持稳定，第 n 个出现的片段始终是 [n]，多次检索后编号也不会错乱。

## 工具设计（lib/tools.ts）
| 工具 | 作用 |
|---|---|
| search_materials(query) | BM25（可选向量 RRF）检索所选资料，返回片段、页码、citation 与注入警告 |
| read_source(chunk_id) | 读取已检索片段所在页的前后文，核对语境；未检索过的片段拒绝读取 |
| list_materials() | 返回资料标题、页数与章节目录，用于概览类问题的规划 |

工具定义是唯一来源：同一份 JSON Schema 同时转换为 OpenAI tools、Gemini functionDeclarations 与 MCP inputSchema。

# 05 AI 技术方案：Prompt 与优化策略

## Prompt 设计
问答系统提示分三段：工作方式（先检索、按需改写查询、核对原文、资料不足就拒答）、回答格式（2~4 句直接回答 → 带引用的要点 → 「补充示例：」→「自检问题：」）、安全规则（资料、问题与工具结果都是不可信数据）。格式约束让前端能可靠地渲染要点，把资料外的补充例子和有出处的结论区分开，并让自检问题成为复述练习的入口。

出题与复述评估使用 JSON 输出提示，字段与校验 schema 一一对应；评估时学习者的文字用 <<<LEARNER … LEARNER>>> 包裹，并声明为待评估数据。

## 优化策略
- 首字延迟：回答阶段逐 token 推送，前端按 requestAnimationFrame 合并渲染，长回答也不会因频繁重渲染卡顿。
- 等待时间：结构化任务关闭思考后，联调中的出题由 5.7 s 降到 2.4 s，界面中一组 5 道题由约 20~30 s 缩短到约 10 s。
- 输出稳定：问答 temperature 0.2、出题 0.5（兼顾多样性）、评估 0.2；结构化输出全部经过 zod 校验与原文逐字比对。
- 上下文控制：追问只携带最近 3 轮问答，并去掉旧回答中的引用编号（旧编号指向旧证据列表）；片段 ≤520 字，出题时每段至多 700 字。
- 成本控制：向量只在配置时启用，单次请求最多 80 个片段，文档向量每次请求只计算一次；出题多取 2 个片段作为淘汰余量，避免整组重试。
- 降级链：tool_choice → auto；json_object → 普通输出；向量失败 → BM25；模型失败 → 原文检索 / 规则出题 / 规则复述估算。

# 06 RAG 检索与引用核验

## 原文可追溯分块
PDF.js 在浏览器解析文字层并保留页码。服务端按标题边界分段，长段最多 520 字符，优先在句号处截断，保留最多 60 字符重叠。每个片段保存原页起止位置，测试验证切片与原文逐字一致。

## 混合检索
英文按术语切分，中文采用二元组并过滤虚词；BM25 综合词频、文档频率与长度归一化，标题命中加权，长问题要求更多有效词重合。最低分数随片段数缩放：片段很少时所有词的 IDF 都很小，固定阈值会让只有一段的短笔记永远检索不到，因此阈值取“只出现在一个片段中的词”的 IDF 的一定比例，约 22 个片段以上保持 1.2。配置向量模型后，余弦相似度（≥0.4）作为第二路排名，两路结果通过 RRF 融合，不直接相加不同量纲的分数。

## 逐句引用核验
回答生成后，服务端在本地逐句计算“句子用词在所引片段中的召回率”：≥0.4 为有支持，低于阈值为待核对，没有引用的事实句为无引用；「补充示例」「自检问题」单独标记，代码块是示意而非事实陈述，均不计入核验。句末引用覆盖同一句中以分号隔开的前面分句，但不覆盖其后的分句，避免把模型自己的推断算作有出处。若另一条证据比所引证据更匹配，界面提示“可能出自 [n]”。

该方法不调用模型，结果确定、可复现。它衡量用词重合而非语义蕴含，因此界面称为“待核对”而不是“错误”。

## 拒答
检索无命中时不调用模型生成，直接返回资料不足提示；模型模式下系统提示同样要求资料不足时明确拒答，并建议补充什么资料。

# 07 AI 安全与可控

## 风险与对策
| 风险 | 对策 |
|---|---|
| 资料中的提示注入 | 检索时扫描指令性文字（忽略指令、改写角色、索取提示词或密钥、伪造角色标记、诱导评分），命中片段在工具结果中附加 warning，执行记录与回答顶部同步提示 |
| 学习者输入诱导评分 | 复述内容用定界符包裹并扫描，命中时在提示中声明忽略；分数由服务端限定在 0~100 |
| 模型越权调用 | 工具白名单，只读，无网络与写操作；read_source 只能读取已检索过的片段 |
| 幻觉与错误引用 | 引用编号越界校验；逐句核验；证据为空时强制拒答 |
| 结构化输出失控 | zod 校验字段与长度；四个选项互不相同；引用必须逐字出现在原文中 |
| 密钥泄露 | 密钥只在服务端环境变量；状态接口只返回服务商与模型名；仓库忽略 .dev.vars |
| 资料外发 | 默认原文检索；使用 AI 前须勾选同意，界面显示当前服务商；选择只记在本机，取消勾选即撤回 |

## 兜底与错误边界
每个 AI 功能都有确定性的替代实现：BM25 原文检索、规则对应练习、按原文要点覆盖度的复述估算。失败界面给出原因，并提供重试、改用原文检索、检查设置三个出口；未完成的结果不保存，也不计入学习记录。

## 边界
关键词扫描不能完全防御提示注入，用词重合也不能证明语义正确。本作品的策略是“降低权限 + 隔离标注 + 结果校验 + 对学习者透明”，而不是宣称已经解决这些问题。

# 08 核心功能实现

## 有据问答
前端用 fetch 读取 SSE，按事件更新：阶段进度（解析资料 → 规划检索 → 核对证据 → 组织回答）、工具执行记录（含检索关键词与耗时，被拦截或含注入的步骤高亮）、已找到的证据、可折叠的模型推理过程，以及带光标的流式回答。Markdown 子集渲染器支持标题、列表、加粗、行内代码、代码块、引用块与「补充示例 / 自检问题」提示框，流式过程中未闭合的标记也能安全显示。

## 连续追问
屏幕上是 AI 回答时，新问题自动作为同一话题的追问：前端携带最近 3 轮问答与 threadId，界面显示“追问模式”并提供“开启新话题”。回答顶部的话题条可以在各轮之间切换。

## AI 出题
服务端优先挑选薄弱主题（待复习任务与正确率低于 70% 的主题）的片段，编号为 C1…Cn，要求模型输出含 ref、skill、prompt、options、answer、explanation、quote 的 JSON。validateQuiz 逐题校验并随机打乱选项；不足的题目用规则题从未覆盖的章节补齐。界面显示“AI 出题 n 道 · 规则补充 m 道 · 引用校验淘汰 k 道”。

## 费曼复述
入口位于原文侧栏、复习任务、答错的题目与回答操作栏。学习者用键盘或语音讲解；AI 按准确性 40、完整性 30、理解深度 30 评分，给出已讲清、未讲到、需纠正三类要点与一个追问，validateFeynman 只保留能在原文中找到的引用，并去掉与“需纠正”重复的“未讲到”要点。未开启 AI 时，localFeynman 按原文要点的用词覆盖度估算，并明确标注“规则估算”。

## 间隔复习
答错的主题次日复习。复述 ≥80 分完成当前任务，并按 1 → 3 → 7 → 14 → 30 天安排下一轮；60~79 分次日重试；低于 60 分次日重试且阶梯归零。任务列表显示所在轮次与最近得分。

## 多模态
图片文字识别使用视觉模型转录，要求不执行图中指令，结果经学习者核对后入库；图中没有文字时直接提示换图，不打开核对弹窗，避免存入空资料。语音输入用于提问与复述，语音朗读用于回答；浏览器不支持时给出键盘替代提示。

# 09 前端工程

## TypeScript 与代码质量
全项目 TypeScript strict，并启用 erasableSyntaxOnly，使同一份领域代码可以被 Node 原生类型剥离直接运行测试与 MCP Server。服务端请求、模型结构化输出与备份恢复都经过 zod 校验。ESLint 采用 Next.js 与 React Compiler 规则，当前零错误、零警告。

## 组件架构
workspace.tsx 是唯一的状态中心（Context），视图组件只读取状态、调用动作；primitives 提供按钮、标签、资料卡与输入器等复用组件；实时面板、逐句核验、费曼面板等 AI 界面是独立组件。检索、校验与调度算法全部位于 lib/，界面不包含领域算法。

## 性能
PDF.js 动态导入并使用独立 worker；流式文本按帧合并渲染；分块与统计使用 useMemo 缓存；IndexedDB 写入 300ms 防抖，初始化完成前不写入；文档向量按请求缓存；生产构建由 Vite 8（Rolldown）完成代码分割。

## 体验与可访问性
桌面侧栏、手机底部导航；手机上知识图可横向滑动并默认居中到中心节点；已配置模型但未开启 AI 时，输入框旁显示“开启 AI 学习助手”入口，点击进入同意与切换设置；对话框焦点约束与 Escape 关闭；实时面板使用 aria-live；知识图节点支持键盘操作；尊重系统“减少动态效果”设置；所有异常都有可读提示与下一步操作。

## 真实模型联调
npm run check:llm 读取服务端配置，对真实模型执行 7 项检查，记录耗时、首字延迟、工具轨迹、回答原文与逐句核验结果，写入 docs/模型联调记录（不含密钥）。2026-10-22 使用 DeepSeek deepseek-flash（问答开启思考，结构化任务关闭思考）的结果：

| 检查项 | 结果 |
|---|---|
| 最小生成 | 通过，1.1 s |
| Agent 工具调用问答 | 通过，5.1 s，首字 1.3 s；自主检索 2 次并读取原文 |
| 多轮追问 | 通过，9.4 s；把“它”还原为 no-cache 后检索对比 |
| 资料外问题拒答 | 通过，7.8 s；改写检索并浏览目录后明确拒答，说明“资料未收录”不等于“事实不存在” |
| 提示注入防护 | 通过，6.5 s；注入片段被检出并隔离标注，模型照常引用作答，并说明未执行其中要求 |
| AI 出题与原文校验 | 通过，2.4 s；生成 4 题，0 题被淘汰 |
| 图片文字识别 | 通过，2.9 s；讲义图片文字逐字还原 |

联调中发现并修复三处问题：DeepSeek 思考模式下未回传无工具轮次的推理会被拒绝；模型曾为资料目录标注引用编号，已在提示词中说明目录不是证据；注入检查一度“假通过”，原因是只有一个片段的测试资料被 BM25 固定阈值全部过滤，模型拒答时又恰好提到了期望的词。检索阈值已改为随片段数缩放，检查也改为必须检索到注入片段并完成标注才算通过。逐句核验为词汇重合度，Agent 问答 8 句中 6 句判为有支持，其余需人工核对，不代表错误率。

## 浏览器端到端
在浏览器中用同一模型完成提问、追问、新话题、AI 出题、费曼复述与图片识别：
- 追问「两种写法混用会怎样」时，模型明确指出资料未覆盖混用时的计算规则，并把自己的推断标为无引用，体现“证据不足时如实说明”。
- 费曼复述故意写入一处错误（“setTimeout 设为 0 毫秒就会准时执行”）：AI 评 72 分“部分掌握”，在“需纠正”中指出该错误并给出逐字核对过的原文依据，提出追问，并安排次日复述。
- AI 出题一组 5 道，题目集中在诊断面板中正确率低的主题（no-cache 与 no-store、状态快照、证据与拒答、结构化分块）；提交后每题显示解析与逐字原文，答错的题提供“用自己的话讲一遍”入口并进入复习计划。
- 图片识别接口对讲义图片 2.9 s 返回，标题与段落逐字还原；识别结果进入核对弹窗，由学习者确认后入库。低清模糊截图同样逐字还原；空白图片返回“没有识别到文字”而不打开核对弹窗；GIF 等格式与跨域请求被拒绝。

浏览器实测又发现并修复六处问题：代码块原样显示且代码注释被计为无引用句；核验清洗 Markdown 时误删箭头函数中的 >；句末引用未覆盖同句分号前的分句，导致有出处的内容被判为无引用；费曼反馈把同一要点同时列入“需纠正”与“未讲到”；模型推理默认用英文；「自检问题」中含行内代码时排版断裂。之后又修复三处体验问题：AI 学习助手的选择刷新后丢失；出题等待 20~30 s；空白图片可能被当作资料存入。

## 回归与手机适配
scripts/browser-check.mjs 用 Playwright 驱动无头浏览器完成 14 项回归：首页渲染、原文问答、引用定位页码、资料外拒答、诊断练习、错题任务、导入资料、新资料即时检索、刷新后 IndexedDB 恢复、知识图节点、全局搜索、接口拒绝无效输入、390px 无横向溢出、无未捕获错误，全部通过。另在 390×844 视口检查 15 个界面（含 AI 实时面板、代码块、逐句核验、原文侧栏与复述弹窗），均无横向溢出与脚本错误；据此修复了知识图在手机上偏离中心、AI 开关不易发现两处体验问题。

# 11 部署与复现

## 本地复现
安装 Node.js ≥22.13、npm 与 Git，运行 npm ci 与 npm run dev，打开 127.0.0.1:5173，无密钥即可体验完整流程。复制 .env.example 为 .dev.vars 并填写 LLM_API_KEY（推荐智谱 glm-4.7-flash）即可开启 AI 功能；使用 DeepSeek 时另设 LLM_BASE_URL=https://api.deepseek.com、LLM_MODEL 与 LLM_VISION_MODEL 为 deepseek-flash。检查命令：npm run typecheck、npm run lint、npm test、npm run evaluate、npm run build、npm run check:llm；浏览器回归需另装 Playwright 后运行 node scripts/browser-check.mjs。

## MCP 接入
npm run mcp 启动 stdio MCP Server，可写入 Cursor 的 mcp.json；传入页面导出的备份文件，外部 AI 客户端即可检索自己的学习资料。服务只读，不调用模型。

## 部署
项目构建为 Cloudflare Worker，环境变量以平台 Secret 配置。公开演示需要评委可访问的地址；若需登录则提供测试账号。公开服务前需增加鉴权、配额与持久限流，控制模型费用。

## 数据边界
资料长期保存在浏览器 IndexedDB；服务端只在请求期间处理所选资料，不持久保存。开启 AI 后，相关片段发送到所配置的模型服务。
