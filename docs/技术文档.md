## 证据驱动的课程学习工作台

作品主张：把资料中的证据、学习者的理解验证、下一步复习行动连接起来。

# 01 项目概述

## 问题与目标
学习者拥有课程 PDF、阅读材料和个人笔记，却经常无法快速找到问题对应的原文，也难以判断自己是否真正理解。普通的文件管理停留在存储，普通聊天又可能缺少证据回溯和学习行动。

知序围绕一个完整流程设计：导入资料 -> 提出问题 -> 核验证据 -> 完成对应练习 -> 生成复习任务。核心是让“回答从哪里来”和“接下来学什么”可以被检查。

## 目标用户
拥有课程讲义、技术阅读或研究入门材料的高校学习者。当前示例聚焦 Web 开发课程，采用四份项目原创讲义。平台也允许导入其他经过授权的文本课程资料。

## 当前价值
- 原文与引用保留页码、章节和字符位置，减少在聊天结果与 PDF 之间反复查找。
- 无模型时保持可用，并明确展示为原文摘录，便于检查检索本身。
- 学习诊断记录直接形成复习任务，支持返回对应资料。
- 不虚构学习效果、用户数量或模型调用成功记录。

## 可验证成果与限制
已完成可运行网站、核心逻辑测试、浏览器流程回归和小样本开发评测。没有真实用户实验，不能宣称提高学习成绩。尚缺真实大模型调用与正式比赛材料的最终审定。

# 02 需求分析与交互设计

## 主要使用流程
1. 资料管理：导入文字型 PDF、Markdown、TXT，或粘贴学习笔记；预览原文、删除资料、筛选内容。
2. 证据问答：限定资料范围，输入问题，查看检索或模型执行过程、答案及出处。
3. 知识脉络：从资料和章节归属关系浏览结构图，点击节点打开原文。
4. 理解验证：生成资料与主题的对应练习，完成作答后查看每题证据。
5. 复习行动：错题主题次日加入任务，可调整日期、回到资料、记录完成。
6. 数据掌控：资料和记录保存在浏览器 IndexedDB，可导出完整 JSON 备份并恢复。

## 信息架构
工作台聚合真实学习记录；资料库负责输入；问答负责探索；结构图负责浏览；诊断与计划构成反馈环。所有模块共享同一份经过类型约束的学习空间状态，避免重复资料与不一致记录。

## 体验原则
- 回答与原文同屏可达，引用卡片打开证据侧栏。
- 空状态说明下一步，异常不伪装成成功。
- 桌面使用侧边导航，手机改为底部六项导航。
- 对话框支持键盘焦点约束与 Escape 关闭；图节点可以键盘操作。
- 云端调用需要用户明确确认资料发送，默认使用原文检索模式。

## 输入约束
单文件不超过 8MB，单份资料文字不超过 15 万字符，PDF 最多 100 页，最多 40 份资料。扫描 PDF 不能直接提取文字时给出错误提示。图片识别需要真实模型，并在入库前由使用者核对转录结果。

# 03 系统架构与数据流

## 分层结构
浏览器展示层：React 19 与 TypeScript，提供资料导入、学习界面、语音能力检测与原文侧栏。

领域层：结构化分块、BM25 排序、引用标识、练习生成、错题任务规则与统计函数。

存储层：IndexedDB 保存当前空间，备份通过 Zod 校验；服务端不建立跨用户共享的文档缓存。

服务层：Vinext 提供 Next.js App Router 兼容路由，Cloudflare Worker 提供模型接入。保留 Sites 的部署集成。

模型层：可选 Gemini generateContent、Function Calling、Embedding、图片转录。未配置密钥时禁用云端能力。

## 问答数据流
用户选定的资料和问题发送到 /api/study。服务端校验数据、分块；本地检索模式返回真实原文摘录；模型模式将资料检索作为工具能力提供给 Gemini。服务端以 SSE 返回实际执行事件与最终答案。SSE 当前不是逐 token 的文本流。

## 核心数据模型
- StudyDocument：稳定 ID、标题、类型、页列表、创建时间。
- Chunk：资料 ID、页码、章节、原文、起止字符位置。
- StudyAnswer：问题、答案、证据快照、检索类型、执行记录、耗时、模式。
- Attempt：题目、用户选项、正确性、章节、证据和作答时间。
- ReviewTask：主题、资料与页码、到期日、预计用时、完成状态。

历史答案保存当时的证据快照，即使原始资料被删除，仍能说明当时引用了什么；界面明确提示原始资料已移除。

# 04 资料处理与检索方案

## 原文可追溯分块
PDF.js 在浏览器解析文字层并保留页码。Markdown 和文本保留页面内原文。服务端依据标题边界分段，长段按最多 520 字符切块，优先在句号处截断，保留最多 60 字符重叠。每个块保存原页起止位置，并通过测试验证切片与引用原文一致。

## BM25 词法检索
英文按术语拆分，中文采用双字片段并过滤部分常见词与虚词。BM25 综合词频、文档频率和长度归一化，标题命中适度加权。长问题需要更多有效词重合，避免偶然重合导致无关命中。

无命中时返回“当前所选资料中没有检索到足够相关证据”，而不是编造答案。此门槛是词法相关性检查，不能证明检索到的资料足以支持每个结论。

## 可选混合检索
配置 Gemini Embedding 后，查询和片段使用真实嵌入计算余弦相似度，词法与向量结果通过 RRF 排名融合。不同算法原始分数不直接相加。当前最多 80 个片段启用向量分支；超出或服务异常时明确使用 BM25。

当前向量分支没有真实 API 测试结果，也没有持久向量索引。每次重新计算的方式适合小规模原型，正式使用需要评估缓存、隐私边界、成本和延迟。

## 引用核验
输出编号与实际提供的证据列表对应，缺失或越界编号会提示。没有任何证据时，服务端强制使用资料不足提示。编号有效不等于语义支持，参赛前仍需人工标注与事实一致性评估。

# 05 模型 Agent 与多模态

## 受限工具执行
模型只拥有两个资料工具：search_materials 按问题检索课程资料；read_source 读取已检索片段。资料读取范围受服务端白名单限制。模型不能执行 shell、任意网络请求或外部写操作。

初轮要求调用检索工具，后续可重新检索或阅读证据，最多四轮；最后一轮关闭工具，要求给出结果。每个工具返回真实证据标识和引用编号。模型的 thought signature 在工具轮次间原样保留，但界面不展示隐藏思考过程。

## 提示与错误处理
系统提示要求仅依据资料回答、给出引用、资料不足拒答，并将上传文档作为不可信数据。模型限流和接口失败返回明确提示，不转成“成功回答”。没有配置模型时，界面与服务端均提示不可使用。

本设计不能宣称完全解决提示注入。工具约束减少可执行权限，但文档诱导、错误结论和引用语义不一致仍需要对抗测试。

## 图片与语音
图片接口使用 Gemini 转录可见文字，要求不执行图中指令。转录结果先展示给用户核对，再加入资料库，保留为图片转录资料。当前图片识别未真实联调。

语音输入使用浏览器 SpeechRecognition 能力检测，朗读使用 SpeechSynthesis。浏览器缺少支持或拒绝权限时，给出键盘操作替代提示。语音服务行为由浏览器决定，不宣称全部在本机运行。

## API 与密钥
密钥仅保存在被 Git 忽略的本地 .dev.vars 或部署平台 secret 中；浏览器不接收密钥。模型 ID 由服务端配置，避免客户端指定任意端点。云端资料发送需要使用者确认。

# 06 前端工程与实现

## 界面与组件
界面采用安静的纸感色彩和资料工作台布局。工作台、学习视图、问答、弹窗、原文侧栏与共享状态拆为独立模块。通用按钮、资料卡、问题输入器和标签复用，避免各页面出现不同交互规则。

TypeScript 定义文档、证据、答案、练习与计划类型。Zod 在服务端请求和备份恢复时验证输入。长文本使用自然换行与溢出保护，PDF.js 通过动态导入加载。

## 状态管理
当前学习空间在 Context 中维护，资料、提问与作答变化后延迟写入 IndexedDB。初始化完成前不会把空状态覆盖旧记录。失败保存会提示导出备份。云端使用确认只保留在当前会话，不把确认隐式延续到其他浏览器。

## 响应式与可访问性
桌面侧栏与右侧辅助区在窄屏折叠，手机使用底部导航。390px 宽度下六个页面均经过横向溢出检查。按钮具有可读名称，输入有标签，对话框管理焦点，支持减少动态效果偏好。

## 已验证流程
浏览器实际执行：原文问答、引用页码、资料外拒答、完整作答、错题形成任务、任务完成、导入新资料、新资料检索、刷新恢复、图节点与全局搜索。验证浏览器上下文独立于日常用户资料。

## 工程限制
此版为个人单机学习空间，尚不提供跨设备同步或多人协作。移动端虽然无横向溢出，仍需增加真实手机和辅助技术测试。正式部署前应对真实网络进行性能测量，不能把构建成功等同于性能达标。

# 07 测试与检索评估

## 自动化测试
12 项核心与模型模拟协议测试通过。覆盖分块位置、长段边界、技术术语检索、无答案拒答、无效引用、RRF 去重、题目选项、次日复习任务、备份格式、Gemini 工具回传、限流和工具白名单。

14 项浏览器回归检查通过，包含自定义资料检索与刷新后恢复、证据侧栏、诊断到任务的闭环，以及 390px 下六个页面无横向溢出。生产构建与 TypeScript 检查通过。

## 小样本开发集实测
语料为四份原创示例讲义，共 24 个片段；问题为 24 个有答案问题与 6 个资料外问题。配置为 BM25，没有大模型或向量服务。

| 指标 | 本次实测 |
|---|---|
| Recall@1 | 95.8% |
| Recall@5 | 100.0% |
| MRR | 0.979 |
| 资料外问题拒答率 | 100.0% |

每条标注对应一个目标章节，因此这里 Recall@k 也等价于命中率。代码输出语料、问题集 SHA256 和每题命中，支持复现。一次未首位命中的样例为 Promise.then 与 setTimeout 顺序，目标标注“事件循环”，首位结果是“微任务与定时器”。

## 解释边界
评测集与语料均由开发者编写，且相关性门槛经过开发样例修正，因此不是独立测试或泛化证明。没有真实用户学习实验，没有模型事实一致性数据。所有结果只描述当前开发集的检索表现。

正式评测需增加独立授权资料、同义问题、跨段问题、干扰与无答案样例，并人工核验结论是否被引用支持。模型、向量与图像效果必须真实联调后另附结果。

# 08 部署、安全与复现

## 本地复现
安装 Node.js >=22.13、npm 与 Git。运行 npm ci、npm run dev 即可在 127.0.0.1:5173 打开。无 API 时能够验证原文检索和学习流程。运行 npm run typecheck、npm test、npm run evaluate 和 npm run build 复现检查。

模型可选配置 GEMINI_API_KEY、GEMINI_MODEL 和 GEMINI_EMBEDDING_MODEL。更改本地配置后重启服务；部署使用平台 secret，并重新部署。免费额度和模型可用性取决于账号实际状态。

## 部署形态
项目保留 Sites 的 Worker 构建、源码同步与版本部署。新建演示站点默认所有者私有，便于作者先验收。私有链接不能直接当作评委公共体验地址，正式参赛须准备可访问的环境和必要测试账号。

## 数据边界
资料长期保存在本机 IndexedDB。本站检索请求会短暂接收所选资料，应用不持久保存服务端副本。开启云端模型后，所选资料发送给 Gemini；需要用户确认。部署平台和模型服务的日志策略需在正式上线时核查。

## 安全控制与剩余风险
API 检查请求来源和数据格式，限制体积与模型超时。资料作为不可信输入，模型工具限定为检索和已授权片段读取。备份文件经过模式校验，不执行用户 HTML。公开仓库不包含密钥。

词法无命中拒答并不能覆盖全部“有命中但无答案”的情况。提示注入、资料泄露、生成错误和模型费用风险仍需要真实环境测试。扩大为公共服务前，必须增加可靠鉴权、配额与持久限流，不能只依赖当前所有者私有部署边界。

# 09 创新、价值与后续工作

## 作品差异
知序把来源追溯、理解验证和复习行动放在同一个学习空间。资料问答是入口，原文是可检查的依据，诊断和任务则把一次提问延伸为下一步学习。创新主张是这一连续交互，而不是首次提出 RAG 或间隔复习。

## 实现与验证分离
展示中明确区分原文摘录、模型生成、规则结构图和规则练习。评测保留失败样例、配置与语料版本。没有把一个引用编号包装成正确性保证，也没有宣称未经测量的学习提升。

## 社会与应用价值
潜在价值在于降低从课程资料中查证知识的成本，让自主学习过程更透明。面向学校课程可扩展为教师提供授权资料、学生自主探索和反馈的辅助工具。商业模式与持续付费意愿仍需真实访谈验证，目前没有收入或用户增长数据。

## 正式参赛前优先工作
第一优先：真实 Gemini 问答、工具调用、错误恢复与图片联调；在独立课程资料上比较 BM25 与混合检索，并人工核验引用语义。

第二优先：收集真实学习者反馈，修复关键可用性问题；完善学习练习质量和多轮上下文；测量延迟与费用，建立公共服务鉴权和配额。

第三优先：填写真实队伍信息，建立 GitHub/Gitee 评审仓库，保留后续实际提交历史，制作 5-8 分钟、至少 1080p、普通话讲解的正式视频。

## 团队与 AI 辅助声明
项目使用 AI 编程助手协助设计、编码、测试和文档。队伍成员须实际阅读、修改、验证并解释核心逻辑。团队姓名、学校、分工和教师信息由参赛者确认，本文不替参赛者虚构身份或贡献。
