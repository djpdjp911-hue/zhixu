## 正式提交前的必要工作

- [ ] 真实 API 联调：至少一次工具检索问答、工具原文核对、多轮错误恢复。
- [ ] 真实向量检索评测：与 BM25 对比，解释成本和收益；没有验证就不要宣传为完成。
- [ ] 图片识别：核验清晰讲义、低清图片、无文字图片与错误情况。
- [ ] 添加至少 2 门真实且有使用授权的课程资料，避免只演示内置讲义。
- [ ] 扩展独立评测问题，包含同义表达、跨章节、多跳问题、无答案问题及干扰资料。
- [ ] 人工核对模型每条结论的证据支持，记录错误、改进与复测。
- [ ] 邀请真实用户试用并保留同意、反馈和问题记录；不虚构学习提升数据。
- [ ] 队伍名称、学校、队员姓名与实际分工、指导教师确认。
- [ ] 每名队员理解核心代码，能解释 BM25、RRF、工具白名单和数据流。
- [ ] GitHub / Gitee 仓库建立并保留后续真实提交历史，授权评审访问。
- [ ] 正式技术 PDF <=30 页，清除“待填写”，补入真实模型测试记录。
- [ ] 5-8 分钟 MP4、>=1080p、普通话讲解，真实展示模型亮点。
- [ ] 如提供在线演示：评委可访问、服务持续可用、需要时提供测试账号。
- [ ] 当前 Sites 演示是所有者私有访问，不能直接交作公共评审地址。
- [ ] 核查公开仓库无密钥、无隐私材料、开源依赖标注和许可证保留。
- [ ] 官网报名、缴费、组别与最终提交入口核查。

## 评分对应与优先级

1. AI 深度 35%：优先完成真实工具调用、引用核验、RAG 与错误兜底。当前最大缺口是实测而非代码数量。
2. 创新 25%：围绕“证据 -> 理解验证 -> 错题任务”的连续体验，证明与普通资料聊天的差异。
3. 前端工程 10%：组件职责、类型、性能、状态与真实交互。
4. 实用性 10%：真实课程和真实试用反馈。
5. 体验 10%：桌面/手机、证据侧栏、异常反馈和无障碍。
6. 价值 10%：解释目标用户、应用场景、持续使用价值和费用约束。

一等奖由评审及同组作品水平决定。此清单用于提高完成度，不构成获奖承诺。
